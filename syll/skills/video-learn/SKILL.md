# 视频示教学习

从用户提供的视频链接中，自动完成：下载 → 转录 → 分析 → 提炼操作流程 → 保存为可复用 skill。

**核心原则：流程明确的步骤自动推进，该确认的地方才确认。每一步都发 progress message。**

## 适用场景

- 用户直接丢一个视频链接（B站、YouTube 等）
- "帮我学会用 XX 软件做 YY"
- "从视频里学习怎么用 XXX"

## 端到端流程

收到视频链接或学习请求后，**自动按顺序执行以下所有步骤**，中间不需要用户再推。每完成一步发一条 progress message 告知进度。

### Step 1：下载视频音频

```bash
yt-dlp -x --audio-format mp3 -o "<工作目录>/%(title)s.%(ext)s" "<视频URL>"
```

- 工作目录用临时目录，如 `C:\Users\<user>\AppData\Local\Temp\video-learn\`
- 如果下载失败，报告错误并提示用户检查网络

**Progress message**: "视频下载完成，正在转录语音..."

### Step 2：转录语音

```python
import whisper
model = whisper.load_model("base")
result = model.transcribe("<音频文件路径>", language="zh")
transcript = result["text"]
```

- 将转录文本保存到工作目录的 `transcript.txt`
- 这一步可能需要几分钟，提前告知用户

**Progress message**: "转录完成，正在分析内容并提炼操作步骤..."

### Step 3：分析内容，提炼操作步骤

阅读转录文本，自动完成以下分析：

1. **识别目标软件**：视频讲的是什么工具（画图、Excel、PS 等）
2. **提炼操作步骤**：从转录中提取出清晰的步骤列表，去除口语化的废话
3. **识别关键参数**：视频里提到的具体数值、选项、路径
4. **判断是否有替代方案**：如果 GUI 操作可以用 CLI/脚本实现（如 Pillow 替代画图），记录两种方式

### Step 4：生成 skill

自动创建 skill，不需要用户提示：

1. 确定 skill 名称：`<软件名>-<操作名>`（如 `image-resize`）
2. 创建目录：`C:\Users\11320\.syll\workspace\skills\<skill-name>\`
3. 编写 `SKILL.md`：包含 description、触发词、操作步骤、注意事项
4. 如果涉及可脚本化的操作，在 `scripts/` 下编写 Python 脚本
5. 测试脚本确保能正常运行

**Progress message**: "分析完成，已生成 skill：<skill-name>"

### Step 5：向用户报告

最终报告包含：

1. **视频摘要**：一两句话说视频讲了什么
2. **提炼的步骤**：编号列表
3. **生成的 skill**：名称、位置、支持的功能
4. **如果用户有具体操作需求**（比如"调到 114×514"）：先用生成的 skill 执行操作，展示结果，再报告 skill 已保存

**不需要问"要不要保存为 skill"——默认保存。** 用户可以后续要求修改或删除。

### 需要确认的场景

- 复现操作涉及 GUI 控制时（可能影响用户正在用的软件）
- 要删除或覆盖已有文件时
- 要发送文件到外部时

其他步骤（下载、转录、分析、生成 skill、测试脚本）全部自动推进。

## 用户中途提了具体需求怎么办

用户可能在视频处理过程中直接提需求（比如"调到 114×514"）。处理策略：

1. **先完成当前步骤**（不要中断下载/转录）
2. **转录完成后，先执行用户的操作需求**（用 CLI/脚本完成）
3. **然后把这次操作的经验沉淀到 skill 里**
4. **最后报告结果和已保存的 skill**

顺序：转录 → 执行需求 → 沉淀 skill → 报告

## 注意事项

- yt-dlp 下载失败时，提示用户检查网络或手动提供视频文件路径
- Whisper 转录可能需要几分钟，提前告知
- 视频教程的软件版本可能与用户本地不同，操作路径可能需要调整
- 如果 GUI 操作可用 CLI/脚本替代，优先用脚本方案（更可靠、可复现）
- 生成的 skill 要实际测试，不要写完就不管了
